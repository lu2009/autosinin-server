## 三个待确认项

### 1. TLV 0x154 不是常量

| 场景 | 值 |
|---|---|
| 本次第一次组包 | 7532 |
| 本次约 258 秒后 | 7790 |
| Frida 触发静默取票 | 0 |
| 再次触发 | 0 / 12955 |
| 密码页登录（2026-11-28 20:40，uin 3937903488） | 63089 / 63266 / 63269 |

反编译 `oicq.wlogin_sdk.tlv_type.tlv_t154`：`get_tlv_154(int i)` 把参数原样写入。三个调用点（`request/e0`、`request/l`、`request/n`）都传 `session.m.g`，即会话上下文里的一个 int 字段。

结论：**0x154 必须等于外层 seq 的假设不成立**（本次 seq=1，0x154=7532）；但"恒为 0"也与真机不符。

补充：第二次抓包（在密码页手动登录）仍然只产生 `wtlogin.exchange_emp` + `wtlogin.log_report`，且 `tlv_t106` 一次都没有构建，说明 QQ 走的是本地保存凭据的快速登录，未走密码 TLV 路径。真正抓 `wtlogin.login` 需要一个在该设备上没有保存凭据的账号。

### 2. 内层序号

真机内层头第三个 short 为 `0001`，本实现固定写 `0`。语义未确认（可能是登录尝试序号）。

### 3. 多余的 7 个 TLV

本实现扫码路径比真机静默取票多带 `0x106 0x191 0x511 0x516 0x521 0x525 0x548`。其中：

- `0x106` 在扫码路径装的是 a1，真机该路径没有
- `0x511`（可登录域名列表）、`0x516`、`0x521`、`0x525`、`0x548` 均为本实现自行添加
- `0x191` 为 `0x82`

是否为多余，需要一次真正的 `wtlogin.login` 抓包对照（本次未捕获到密码登录）。
